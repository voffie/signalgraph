title: Client
description: Use the generated SignalGraph client to publish messages and register handlers.

The [generator](/cli/generate/) writes `index.ts` to the configured output directory. Import `Client` from that directory and yield it inside an Effect. Provide the broker layer to that Effect. Regenerate the file when the schema changes.

```ts
import { Client } from "../generated/index.ts";

const client = yield* Client;
```

The generated module exports `messageGraph` for deployment tools such as the [Cloudflare adapter](/adapters/cloudflare/). It also exports the `Client` type and one payload type per message, such as `OrdersCreatedPayload`. Inline publish calls and handlers infer their payload types directly from the schema. Use the exported types when another module needs to name them.

## Handle messages

```ts
yield* client.billing.handle(({ payload, metadata }) =>
  Console.log("Handling order", payload.orderId, metadata.messageId)
);
```

Register a handler for each declared consumer before calling `start()` or `listen()`. The handler receives the decoded payload and metadata for the delivery. Use `messageId` to identify the message, `correlationId` to follow related messages, and `retryAttempt` to distinguish attempts. The first attempt is numbered `1`.

Publishing a follow-up message inside a handler gives it a new message ID while preserving the correlation ID.

## Publish messages

```ts
yield* client.ordersCreated.publish({ orderId: "order-123" });
```

`publish` encodes the payload using its message schema. An invalid payload fails with `InvalidPayloadError`. A transport failure can return `ConnectionError`. A broker confirmation establishes transport acceptance. Handler completion is a separate event.

## Start and shut down

- `start()` validates your handlers and starts the broker adapter. With RabbitMQ it returns after starting consumption. With Cloudflare Queues it processes the current batch and returns when it is settled.
- `listen()` starts the configured integrations and the client, then waits for a shutdown signal. On the first SIGINT or SIGTERM, the client stops accepting deliveries and waits up to `gracePeriod` for active handlers. The default is 30 seconds. A second shutdown signal skips the rest of the wait.

A publish-only process can yield `Client` and publish. With RabbitMQ, start the consumer application first so its topology exists. With Cloudflare Queues, deploy the queues before publishing.
