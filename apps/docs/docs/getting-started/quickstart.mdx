---
title: Quickstart
description: Generate a SignalGraph client, start a RabbitMQ consumer, and publish your first message.
---

This example declares an `orders.created` message and a Billing consumer. The publisher and consumer run as separate processes and import the same generated client.

Start with [installation](/getting-started/installation/) and a running RabbitMQ instance. For a local demo, run this command in a separate terminal and leave it running:

```sh
docker run --rm --name signalgraph-rabbitmq -p 127.0.0.1:5672:5672 -e RABBITMQ_DEFAULT_USER=signalgraph -e RABBITMQ_DEFAULT_PASS=signalgraph rabbitmq:4-management
```

The URL in the examples below uses those demo credentials. Use your own broker URL if you already have RabbitMQ.

## 1. Declare the message and consumer

```ts title="src/schema/schema.ts"
import { Schema } from "effect";
import { consumer, message } from "signalgraph";

export const OrderCreated = message({
  name: "orders.created",
  schema: Schema.Struct({ orderId: Schema.String })
});

export const Billing = consumer({
  name: "billing",
  message: OrderCreated
});
```

## 2. Generate the client

```ts title="signalgraph.config.ts"
import { defineConfig } from "signalgraph/config";

export default defineConfig({
  schema: "./src/schema/schema.ts",
  out: "./generated"
});
```

From the project directory, run `npx signalgraph generate` or `pnpm exec signalgraph generate`. The CLI writes `generated/index.ts`. Regenerate it after changing the schema, or use [watch mode](/cli/generate/).

## 3. Run the consumer

```ts title="src/handlers.ts"
import { RabbitMQBroker } from "@signalgraph/adapter-rabbitmq";
import { Console, Effect } from "effect";
import { Client } from "../generated/index.ts";

const program = Effect.gen(function* () {
  const client = yield* Client;
  yield* client.billing.handle(({ payload }) =>
    Console.log("Billing received order", payload.orderId)
  );
  yield* client.listen();
});

await Effect.runPromise(
  program.pipe(
    Effect.provide(RabbitMQBroker({ url: "amqp://signalgraph:signalgraph@localhost" }))
  )
);
```

Run `node src/handlers.ts`. Wait for the log confirming that RabbitMQ topology was declared and consumers registered before starting the publisher.

## 4. Publish a message

```ts title="src/publish.ts"
import { RabbitMQBroker } from "@signalgraph/adapter-rabbitmq";
import { Effect } from "effect";
import { Client } from "../generated/index.ts";

const program = Effect.gen(function* () {
  const client = yield* Client;
  yield* client.ordersCreated.publish({ orderId: "order-123" });
});

await Effect.runPromise(
  program.pipe(
    Effect.provide(RabbitMQBroker({ url: "amqp://signalgraph:signalgraph@localhost" }))
  )
);
```

In a second terminal, run `node src/publish.ts`. The consumer should print `Billing received order order-123`. Press Ctrl+C in the consumer terminal to stop it and drain in-flight work. If you started the demo container, stop it from its terminal too.

For a flow where one handler publishes a follow-up message and you can inspect the resulting trace, see [Devtools](/integrations/devtools/).
