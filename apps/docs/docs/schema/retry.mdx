---
title: Retry
description: Configure fixed or exponential retry for a consumer.
---

Retry policies apply to a consumer's failed delivery. `maxAttempts` includes the initial delivery, so `maxAttempts: 3` allows two retries. Without a retry policy, a failure moves straight to the configured dead-letter or discard behavior. With RabbitMQ, connection loss can also cause unacknowledged deliveries to be redelivered independently of this policy.

## Fixed delay

```ts
import { consumer } from "signalgraph";

export const Billing = consumer({
  name: "billing",
  message: OrderCreated,
  retry: { type: "fixed", delay: "1 second", maxAttempts: 3 }
});
```

Both retries use the same delay.

## Exponential delay

```ts
import { consumer } from "signalgraph";

export const Billing = consumer({
  name: "billing",
  message: OrderCreated,
  retry: {
    type: "exponential",
    initialDelay: "1 second",
    factor: 2,
    maxDelay: "5 seconds",
    maxAttempts: 5
  }
});
```

The four retries wait 1, 2, 4, and 5 seconds. The factor defaults to `2` and `maxDelay` is optional. Use finite durations, a finite factor of at least `1`, and a positive integer for `maxAttempts`.

## After the last attempt

With RabbitMQ, failed deliveries go to `<consumer-name>.dlq` by default. Set `dlq: false` to discard them after the final attempt. Check the reason and reconcile any side effects before replaying a dead-lettered message. Design handlers to tolerate duplicate deliveries, including when replaying.
